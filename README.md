# Описание проекта: Telegram-бот-стилист по погоде

## 1. Что будет видеть пользователь

1. Пользователь заходит в Telegram-бота и видит:
   - приветственное сообщение с коротким описанием:  
     *«Я подсказываю, что надеть по погоде на весь день»*
   - кнопки/меню:  
     - `Совет на сегодня`  
     - `Настройки`  
     - `Изменить район`  
     - `Изменить стиль`

2. При нажатии `Совет на сегодня` бот присылает:
   - краткий сводный прогноз, например:  
     *«Сегодня в Амстердаме от +7 до +15, ветер до 8 м/с, дождь вечером»*
   - рекомендацию в одном сообщении:  
     *«Надень джинсы, худи и лёгкую ветровку, возьми зонт и шарф»*
   - дополнительные кнопки:
     - `Показать прогноз по часам`
     - `Сделать теплее` / `Сделать холоднее` (быстрая подстройка)

3. В разделе `Настройки` пользователь видит:
   - выбор профиля термочувствительности:
     - `Мне всегда холодно`
     - `Норм`
     - `Мне всегда жарко`
   - выбор стиля одежды: `casual` / `офис` / `спорт` / `минимализм`
   - выбор города по умолчанию
   - настройку времени ежедневной рассылки (например, 7:30 утра)

4. Дополнительные возможности:
   - указание района, где пользователь будет сегодня (дом, кампус, другой район города)
   - отдельные предупреждения:  
     *«Сегодня сильный ветер, не бери зонт-трость»*,  
     *«Высокий УФ-индекс, нужен SPF»*
   - короткие шутливые комментарии в ответе бота

---

## 2. Какие задачи необходимо выполнить

1. **Аналитика и проектирование**
   - описать пользовательские сценарии (первый запуск, ежедневное использование, изменение настроек)
   - определить, какие погодные параметры нужны (температура по часам, осадки, ветер, УФ-индекс)
   - придумать правила перевода погоды в рекомендации по одежде

2. **Интеграция с погодным API**
   - выбрать погодный сервис
   - реализовать модуль запроса почасового прогноза на день
   - нормализовать данные (единый формат, нужные единицы измерения)

3. **Модуль рекомендаций (ядро бота-стилиста)**
   - разработать набор правил:
     - учёт минимальной и максимальной температуры за день
     - учёт перепадов температуры в течение дня
     - учёт осадков, силы ветра, жары и УФ-индекса
   - учесть профиль пользователя (*«мне всегда холодно / жарко»*)
   - учесть выбранный стиль одежды (ограничения по типам вещей)
   - подготовить текстовые шаблоны рекомендаций и шутливых комментариев

4. **Telegram-бот**
   - зарегистрировать бота и настроить токен
   - реализовать команды и меню (`/start`, `Совет на сегодня`, `Настройки` и др.)
   - сделать обработчики настроек (термочувствительность, стиль, город, район)
   - реализовать обработку ошибок (нет данных погоды, некорректный ввод и т.п.)

5. **Ежедневная автоматическая рассылка**
   - реализовать планировщик задач
   - связать планировщик с хранящимися настройками времени рассылки
   - обеспечить сохранность подписок и возможность включать/отключать рассылку

6. **Хранение данных и персонализация**
   - спроектировать простую базу данных (пользователь, настройки, время рассылки, предпочтения)
   - реализовать слой доступа к данным
   - предусмотреть обновление схемы при добавлении новых настроек

7. **Инфраструктура, тестирование и документация**
   - настроить репозиторий, CI и линтеры
   - написать юнит-тесты для модуля погоды и модуля рекомендаций
   - подготовить README и пользовательскую документацию
   - подготовить диаграммы взаимодействия компонентов (Mermaid/UML)

## 3. Оценка времени на задачи

| № | Задача                                      | Оценка времени |
|---|---------------------------------------------|----------------|
| 1 | Аналитика, сценарии, набор правил           | 8 ч            |
| 2 | Выбор и интеграция погодного API            | 8 ч            |
| 3 | Модуль рекомендаций (правила + шаблоны)     | 10–12 ч        |
| 4 | Реализация Telegram-бота (команды, меню)    | 10 ч           |
| 5 | Настройки пользователя + сохранение в БД    | 8 ч            |
| 6 | Планировщик ежедневной рассылки             | 4–6 ч          |
| 7 | Доп. фичи (район, стиль, предупреждения)    | 8 ч            |
| 8 | Тесты (погода, рекомендации, логика бота)   | 8 ч            |
| 9 | Документация и диаграммы                    | 6 ч            |

Итого: примерно **70–75 человеко-часов**  
При команде из 4 человек это около **18–20 часов на человека**.

## 4. Роли в команде (4 человека)

1. **Участник 1 — тимлид и аналитик**
   - финализирует идею и пользовательские сценарии
   - отвечает за модуль рекомендаций (правила, шаблоны текстов)
   - координирует работу команды и следит за дедлайнами
   - отвечает за общее итоговое описание проекта

2. **Участник 2 — backend: погода и БД**
   - выбирает и подключает погодный API
   - реализует модуль загрузки и нормализации прогноза
   - проектирует и реализует базу данных настроек пользователей
   - пишет слой доступа к данным

3. **Участник 3 — разработчик Telegram-бота**
   - настраивает бота (команды, меню, обработчики сообщений)
   - интегрирует бота с модулем погоды и модулем рекомендаций
   - реализует настройку термочувствительности, стиля, города и района
   - реализует планировщик ежедневной рассылки

4. **Участник 4 — инфраструктура, тесты и тексты**
   - настраивает репозиторий, CI и проверки качества кода
   - пишет юнит- и интеграционные тесты
   - помогает шлифовать формулировки советов и шуток
   - рисует диаграммы (Mermaid/UML) и готовит техническую документацию

### Краткое описание структуры проекта

- `weather_stylist/` — основной пакет приложения
  - `domain/` — предметная область: модели погоды и пользователя, чистые правила подбора одежды
  - `use_cases/` — сценарии: «совет на сегодня», обновление профиля, настройка ежедневной рассылки
  - `adapters/` — адаптеры:
    - `telegram/` — обработка команд бота, формирование текстовых ответов и кнопок
    - `weather_api/` — работа с внешним погодным API и преобразование JSON в доменные модели
    - `persistence/` — сохранение и загрузка настроек пользователя из хранилища
  - `infra/` — инфраструктура: конфиги, планировщик рассылки, логгирование и `main.py` как точка входа

- `tests/` — автотесты для доменной логики, сценариев и адаптеров

- `docs/` — архитектура и диаграммы (Mermaid/UML), используемые в описании проекта и документации
